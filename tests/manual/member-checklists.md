# POST-03：角色清單驗收與發布

## 資料及授權

家庭信任模式：有效行程 Bearer 才能取得該行程的四個成員及私人清單。角色 UUID 僅代表選擇，非登入憑證。爸爸／媽媽／弟弟／我的 UUID 在 Migration／行程建立時產生並持續保存；讀取不重建刪除的角色。

Migration `20261118020000_member_checklists.sql` 新增 `trip_members`、`personal_checklist_items`、`personal_checklist_mutation_requests`。清單以行程、成員、種類隔離，複合外鍵、強制 RLS 與 service_role-only RPC；保留 item version 與 Idempotency-Key。必備清單維持共享。

UI 沿用現有卡片與按鈕；新增角色選擇、頁首目前角色切換按鈕、舊清單確認匯入。Prototype 未修改，無新套件。

## 舊清單遷移

舊 IndexedDB 無行程及角色歸屬，絕不自動上傳。選好角色後，清單頁若發現舊資料，會顯示數量及目的角色，使用者明確確認後才匯入。匯入前保存目的行程及成員綁定；逐項以穩定冪等鍵新增，保留名稱及勾選，不覆蓋遠端清單。失敗可重試，儲存拒絕時不開始上傳。完整完成後標記，避免再次匯入；原始 IndexedDB 永遠保留。

回復：回退應用程式時不刪除新表；舊 IndexedDB 仍可由原版讀取。新版產生的雲端私人資料仍留於資料庫，舊版不會顯示它們。不得以刪表或清空本地資料做回退。

## 追加驗收（2026-11-19）

- 修正一般卸載（例如暫時性授權 API 失敗）只停止背景儲存，不刪私人快照；明確切換角色／失效授權仍清除。新增對應回歸測試。
- 修正私人清單離線同步時間改讀目前角色及清單種類的快照，不使用共用必備清單資訊。
- Chrome＋隔離 PGlite＋真實 handler：舊行李及待辦共兩筆，明確確認匯入；第一筆後端提交後模擬 503，重試成功且行李僅一筆，原勾選狀態保留，待辦恢復。已完成標記使重新進入不再提示匯入。
- 透過本機測試控制台移除角色紀錄，重新整理顯示選擇畫面；重新選媽媽後兩種清單可恢復。
- 以 navigator.onLine getter 與 online／offline 事件模擬離線，驗證角色切換、新增、勾選、改名與刪除停用，私人快照可讀；這不是實際斷網或 Service Worker 全套驗收。
- 模擬重新連線時全部 API 回傳 503，顯示暫時無法驗證；再次模擬離線後原角色及私人待辦快照仍在，恢復 API 及連線後正常載入。
- 第二個行程首次仍要求選角色，選爸爸未混入第一行程媽媽的待辦；返回第一行程自動恢復媽媽及原待辦。
- 新 SQL 測試補上 TAP 輸出，以相容 `supabase test db`。

## iPhone 手動步驟

前置：先完成後端及前端發布。使用可撤銷的有效私人連結，勿將連結、權杖或真實清單放入截圖／測試報告。

1. Safari 首次開啟連結，確認網址 fragment 已清理；顯示「請問你是哪位成員？」及四個人物頭像。
2. 選媽媽；行李與待辦各新增、修改、勾選測試項目，再重新整理。確認角色與內容不變。
3. 關閉 Safari 分頁／終止 Safari，再重開一般站點網址；確認授權及媽媽恢復，資料不變。
4. 由頁首角色按鈕切爸爸；確認兩種私人清單不混入媽媽資料；新增爸爸項目後切媽媽，原資料仍在。必備清單兩者相同。
5. Safari「分享 → 加入主畫面」，首次由圖示開啟。若本地角色未同步，必須顯示選擇；選媽媽可讀回兩種清單。不得用空清單覆蓋遠端。
6. 關閉主畫面 App、重開、重啟 iPhone 後重開；確認角色及清單持續恢復。舊安裝也執行同流程。
7. 在可丟棄的測試安裝清除網站資料後，以有效私人連結重新取得行程授權，重新選媽媽；確認雲端資料回復。若沒有憑證，應顯示需私人連結，不建立角色或清單資料。
8. 連線成功讀取兩種清單後開飛航模式：只能讀已有未過期快照，不能新增、修改、刪除、勾選或切換；缺快照顯示不可用，非寫入空清單。恢復連線重新確認成員及資料。
9. 模擬 API 失敗／回應中斷；確認失敗提示、重試保留同一冪等鍵；重新載入後沒有重複項目、清空或靜默覆蓋。
10. 以兩個獨立測試行程驗證本地選擇分開、角色 UUID 不同；改用其他行程 member_id 的請求必須拒絕。撤銷私人連結後連線重開應清除憑證與對應快照。
11. 若主畫面未恢復 Access Token：記錄 iOS 版本、安裝前後、同源 Cookie／localStorage 可用性及啟動狀態（不記錄值）。沿用 POST-02 的 180 天同源 Cookie 後備與撤銷；重新取得有效私人連結，禁止改用永久權杖。

## 發布順序

1. 審查、備份及核對遠端 Migration 後，套用新增 Migration（不 reset 遠端）。
2. 部署包含成員與私人清單路由的 Edge Function，驗證有效／無效 Bearer、外行程成員、版本衝突及錯誤不清空。
3. 經 PR 合併後發布前端，完成上述實機步驟。不得自行合併 PR。
4. 只在必要驗收完成後更新 POST-03；POST-02 的既有 iPhone 待驗收獨立保留。

## 2026-11-24｜三種清單各自進度與女生頭像

此決策取代前述必備清單共用勾選：必備項目定義仍共用，勾選與進度依角色保存；行李與待辦維持個人清單。`20261124020000_member_essential_progress.sql` 新增進度及冪等紀錄表，強制 RLS、複合外鍵與 service_role-only RPC。角色 API 的種類增加 `essentials`；舊共享 endpoint 保留相容，但舊 is_done 不歸屬任何成員。回退不刪表，重新發布新版可恢復個人進度。

本機使用實際 Edge handler／Postgres adapter 與 PGlite Migration、合成資料，390 × 844／1440 × 900 驗證：我在三種清單勾選後，媽媽三種均未勾；切回我三種均恢復，重新整理必備進度仍在。角色選擇頭像「我」為與媽媽不同的短髮女生；無水平溢位。SQL 驗證四角色初始隔離、共享名稱、個人勾選、跨行程拒絕、冪等及版本衝突、刪除清理、權限及 RLS。實際 iPhone／PWA／完整瀏覽器程序重啟仍待原 POST-03 驗收。

追加手動步驟：用四角色逐一勾選三種清單，確認其他角色不受影響；同一角色換裝置／重開可恢復。必備新增、改名、刪除仍共用。首次升級的必備勾選各自從未完成開始；行李與待辦既有個人進度不變。
